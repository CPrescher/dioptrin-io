# Using the upstream FabIO suite as the acceptance corpus

Full reading parity remains the target for every entry in
`FORMAT_COVERAGE.md`. Native counts from a few synthetic files, or generic TIFF
and HDF5 success, do not establish that target.

`scripts/fabio_suite_parity.py` loads **all 35 codec test modules** directly from
the pinned FabIO checkout. It executes their original unittest assertions with
the installed, version-matched FabIO reference, and intercepts successful reader
calls to compare the **same actual files** against `examples/parity_probe.rs`.
This includes files generated by upstream tests, downloaded detector files,
outer-compressed files and stacks. All frames exposed by each matched reader
are compared, including shape, scalar dtype and SHA256 of canonical
little-endian sample bytes. Comparisons never coerce dtypes, use tolerances or
mask reserved values to hide differences. Explicit consumer/reference views
are selected and recorded separately as described below. The d*TREK and EDF
text-header fields are also compared.

The report records test IDs and source hashes, codec source hashes, source-file
and download hashes, the Rust source hashes and executable hash, aliases,
reference errors/skips, unsupported readers, native rejections and differences.
The measured executable is copied to a private location so concurrent Cargo
checks cannot change the binary mid-run. The script exits nonzero while the
full gate is incomplete; reference unittest success alone cannot make it green.

This is a comparison bridge, not a Python API shim: Python unittest assertions
still execute against reference objects, with native read results checked
alongside them. Complete detector-specific header schemas, native discovery,
direct stream APIs, read paths bypassing `.read`, and intentionally different
malformed-file behavior remain explicitly unverified. A passing count comparison
must not be presented as passing those additional reading contracts. Writing,
in-place Python object manipulation and numerical statistics are not production
APIs of this I/O crate; writer tests still provide useful generated reader inputs.

## Reproduction

Use a test-only Python environment. Exact packages used for this run are in
`fabio-parity/reference-requirements.txt`; Python is not used by the Rust reader
or its tests. Keep the downloaded corpus outside the repository.

```sh
python3.13 -m venv /tmp/dioptrin-io-fabio-suite-env
/tmp/dioptrin-io-fabio-suite-env/bin/python -m pip install -r docs/fabio-parity/reference-requirements.txt
git clone https://github.com/silx-kit/fabio.git /tmp/dioptrin-io-fabio-2026.6.0
git -C /tmp/dioptrin-io-fabio-2026.6.0 checkout 9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece
cargo build --release --locked --example parity_probe --all-features
/tmp/dioptrin-io-fabio-suite-env/bin/python scripts/fabio_suite_parity.py \
  --fabio-source /tmp/dioptrin-io-fabio-2026.6.0 \
  --data /tmp/dioptrin-io-fabio-corpus \
  --probe target/release/examples/parity_probe --probe-timeout 300 \
  --tiff-reference-library /opt/homebrew/lib/libtiff.6.dylib \
  --report /tmp/dioptrin-io-fabio-acceptance.json
```

Omitting `--modules` is essential for the full inventory. A selected-module run
records that restriction in its report. The exact source commit is checked, and
installed reference codec hashes must match the pinned sources for a green gate.

The upstream test utility's old edna-site HTTPS endpoint has a certificate-host
mismatch on this host. The harness explicitly uses the working official
`https://www.silx.org/pub/fabio/testimages` mirror, retaining file hashes. The
test environment explicitly registers its installed hdf5plugin codecs
(`--reference-filters bundled`, the default), preventing unrelated host HDF5
plugins from causing ABI conflicts. This policy is recorded and does not affect
the production native reader. OpenJPEG must be discoverable separately for the
optional Glymur test variants; the Pillow JPEG2000 tests run independently. On
this macOS host, `DYLD_LIBRARY_PATH=/opt/homebrew/lib` makes the installed
OpenJPEG 2.5.4 available to the test-only Python process. The report records its
loaded version. No user configuration file is changed.

## Current evidence and remaining work

Schema 4 retains earlier admission statuses and separates source samples from
explicit reference views and modeled reconstruction:

| Status | Meaning |
|---|---|
| `decoder_missing` | No format-specific Rust read entry point is implemented; a generic container reader may still decode some pixels. |
| `test_adapter_missing` | A compiled Rust reader exists, but test plumbing to call it is missing. |
| `feature_disabled` | The optional reader exists but its Cargo feature is absent from this test binary. |
| `native_rejected` | The reader was called and explicitly rejected this variant, storage, source or malformed input. |
| `counts_match` | Every exposed frame's shape/dtype/sample hash matches; semantic header gaps can still remain. |
| `reference_view_match` | An explicitly selected display, inverse-encoding or exact dtype view matches; raw stored samples are recorded separately. |
| `component_view_match` | Original native TIFF units/grids match an independent decoder, and the separately selected display view matches. |
| `reconstruction_match` | An explicit deterministic sparse background view matches; original source components/events are compared independently. |

The executable publishes its compiled features, known readers and adapter
capabilities. Full-feature runs use all native entry points, including explicit
container/legacy/image readers and detector TIFF acquisition headers. A separate
feature-disabled run distinguishes unavailable compilation features from missing
readers. Every original registry entry remains in the ledger.

Current evidence is recorded in `fabio-parity/2026-11-06-tiff-codecs.json`;
the earlier baseline and typed-HDF5 reports are retained. The current report is
a failing full-parity gate, with exact native successes, unsupported layouts,
reference differences and remaining readers kept separate.

The comparison selects external EDF/HDF5 snapshots, R-AXIS expanded intensities
and KCD summed readouts explicitly, recording those policies. Default native
readers preserve original words/readouts. SPE and MRC frame comparisons use fresh
reference `.read(path, frame=i)` objects because pinned inherited frame APIs are
incomplete. Every declared SPE frame is checked. TIFF color channels, palette indices and WhiteIsZero counts remain in source
form. The bridge selects an explicit `Pillow13` or `FabioTiffIo` display view from
the reference backend recorded on the successfully read object; it never retries
a failed native decode through another backend. Bruker LINEAR uses a separate
inverse float-encoding view. Reports retain raw signatures and transformation
provenance. Two defective Pillow planar16 views remain mismatches. Bilevel bool
comparisons use canonical logical 0/1 bytes and retain the reference physical
backing hash separately; historical schema 2 reports are not rewritten.

Pilatus semantic maps are compared directly. For MAR, the bridge explicitly
invokes the pinned binary acquisition-header parser and normalizes only byte
array representation, comparing every field. Complete semantic schemas for the
other formats remain a separate gap. Successful EDF/HDF5 reads expose and hash
all tracked source files in their manifests, including intermediate HDF5 links.

The same-file corpus revealed real cases now supported: nested braces inside
d*TREK values, repeated HiPiC comment keys, EDF binary padding, absent optional
uncompressed Size, legacy compression names, and outer gzip/bzip2 wrappers.
Small independent CC0 regressions complement these files, particularly for
native types, C/Fortran indexing, bounds, truncation and mutation.

Some reference tests intentionally accept incomplete data and fill missing EDF
pixels with zeros. Others tolerate compression garbage, malformed headers or
drop text fields. These are visible native rejections/header differences, not
permission to invent counts or silently repair a source. The repository's
count-preservation contract takes precedence, and each such difference must be
resolved or documented explicitly. The pinned PNM P1/P2 implementation also
fails to advance its row index; native input preserves all rows rather than
adopting that bug. Reference quirks do not remove any format from the target.

## EDF source continuation

The EDF reader now retains general headers, raw repeated fields and the actual
closing-newline boundary, including CRLF and boundaries crossing a 512-byte
block. Local fields override inherited general fields. Compressed storage slots
may contain less than 512 bytes of zero/ASCII-space padding when the declared
slot ends on a 512-byte boundary, while decoded sample counts and checksums remain
strict. A final suffix shorter than 512 bytes containing only zeros and ASCII
whitespace is reported as storage padding rather than another frame.

External payloads are rejected by default. `edf::Options` explicitly selects
snapshot following, optional basename relocation and optional `.gz`/`.bz2`
counterparts when the exact named file is absent. Ambiguous alternatives and
present corrupt files fail. Limits cover the total expanded source bytes and
number of files. Every source, including a compressed original whose payload
was staged, is revalidated around each frame. The parity probe records its
explicit acquisition-file relocation policy.

Some upstream external EDF examples declare 140000 bytes for a 28800-byte image
in a 37376-byte file at offset 8192. These remain rejected because the declared
source window extends beyond EOF. No pixels are invented or silently supplied
from another source. Similarly, partial headers and incomplete compressed
streams remain errors, although the reference may return earlier frames or
zero-fill data. These cases remain visible in the acceptance report.

## MAR345, sparse and rejection continuation

The MAR345 PCK V1 backend compares all exposed upstream reads and independently
qualifies source-correct differences in the pinned decoder's unsigned predictor,
32-bit masks, leading whitespace and big-endian overflow handling. V2/raw variants
remain explicit gaps. See `MAR345_READER.md` and its independent fixture manifests.

d*TREK rank1..32 arrays expose source-ordered 2D planes. The bridge records the
original logical shape and maps leading axes in C order rather than relying on
the reference's incomplete `getframe` API.

Sparse qualification explicitly requires the pinned native Cython densifier with
`NOISY=False`. The Python fallback and stochastic models have different semantics
and are not silently substituted. Every original numeric component, frame pointer
span and event word is compared independently of the derived dense image. The
actual 100-frame corpus has **zero stored events**; nonempty/extreme events and
external/growing source graphs are verified with independent CC0 fixtures. See
`SPARSE_READERS.md`.

On reference input errors the bridge also invokes the native reader with the
same default configuration and available source. Reports distinguish matching
input rejections, unsupported comparison configurations, process failures and
deliberately disabled reference-backend tests. A monkeypatched missing Python
JPEG backend is an environment difference, not a native input rejection.
Direct stream APIs, complete semantic metadata, autodetection, neighboring-file
series and unsupported variants remain in the full-parity gate.

## Rejection audit and captured test inputs

The rejection continuation audits every one of the preceding report's 91 rejected
read events by its original source hash. Repeated calls are retained, while
classification groups the 31 distinct inputs. Input condition and reader action
are independent: a complete image with a wrong size field does not become a well
formed file because an explicit compatibility policy can read its samples.
`rejection-audits/README.md` records the complete classification, evidence and
remaining codec/layout/source-contract work.

The bridge explicitly selects `ExternalWindow::UpToDeclared` for external EDF
windows. The production default remains `Exact`; inline header/payload navigation
is unchanged. Every compared frame records declared/effective window sizes,
source and offset. Missing sample bytes, incomplete codecs and source changes
remain errors. TY5 production output stays I32; the bridge's separately recorded
I32-to-F64 view reproduces the pinned Python API exactly without losing an integer.
Independent dxtbx comparisons establish the original native counts.

Some upstream tests create and remove malformed sources. Use
`--rejected-source-dir /tmp/dioptrin-rejected-inputs` to retain exact rejected bytes
before cleanup. The directory must be outside the repository; reports record
copy hashes and capture failures. Reuse requires the same hash. Process crashes
and unexpected exit codes are `native_process_failure`, rather than input
rejections. Historical gzip timestamps and generated TIFF date fields can prevent
byte-identical reproduction of an old ephemeral source; audit records distinguish
recreated pinned-test cases from exact original source evidence.

Regenerate the complete classification from the three scoped audits with
`scripts/aggregate_rejection_audits.py`. It rejects missing/duplicate source
classifications, incorrect event counts, changed baselines and mismatched test
identities; no case is removed merely because it is malformed.

## TIFF component comparisons and dependency fingerprints

Schema 4 does not fabricate an HWC source array for subsampled YCbCr. The probe
records every original unit/plane hash, physical shape, valid extent, sampling,
chunk origin, storage kind and explicit display policy. Source JPEG headers and
legacy reconstruction windows remain separate from the derived image.

Use `--tiff-reference-library /path/to/libtiff` for independent component checks.
The test-only oracle records the library version/binary hash plus imagecodecs
codec versions and native extension hashes. Lossless LZW decodes the complete
original payload with imagecodecs, preserving padding that libtiff's ordinary
strip read clips. Legacy JPEG uses libtiff RAW components. For aligned modern
JPEG, explicit no-fancy YCbCr decoding followed by inverse nearest-grid decimation
recovers source chroma samples; a reproduced libtiff RAW zero-fill defect makes
that backend unsuitable for this source. Odd unqualified reference grids are
rejected rather than inferred. Missing component-reference support is an explicit
nonmatch, not unverified raw-count success. These are reference/test dependencies;
production readers do not call Python, imagecodecs or system libtiff.

The full report fingerprints Cargo inputs and every vendored dependency file
before/after the run, in addition to native Rust, bridge and executable hashes.
The exact old-LZW backend patch retains its archive/file provenance and licenses.
