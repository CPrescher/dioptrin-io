# Using the upstream FabIO suite as the acceptance corpus

Full reading parity remains the target for every entry in
`FORMAT_COVERAGE.md`. Native counts from a few synthetic files, or generic TIFF
and HDF5 success, do not establish that target.

`scripts/fabio_suite_parity.py` loads **all 35 codec test modules** directly from
the pinned FabIO checkout. It executes their original unittest assertions with
the installed, version-matched FabIO reference, and intercepts successful reader
calls to compare the **same actual files** against `examples/parity_probe.rs`.
This includes files generated by upstream tests, downloaded detector files,
outer-compressed files and stacks. All frames exposed by each matched reader
are compared, including shape, scalar dtype and SHA256 of canonical
little-endian sample bytes. No tolerance, float conversion or reserved-value
masking is applied. The d*TREK and EDF text-header fields are also compared.

The report records test IDs and source hashes, codec source hashes, source-file
and download hashes, the Rust source hashes and executable hash, aliases,
reference errors/skips, unsupported readers, native rejections and differences.
The measured executable is copied to a private location so concurrent Cargo
checks cannot change the binary mid-run. The script exits nonzero while the
full gate is incomplete; reference unittest success alone cannot make it green.

This is a comparison bridge, not a Python API shim: Python unittest assertions
still execute against reference objects, with native read results checked
alongside them. Complete detector-specific header schemas, native discovery,
direct stream APIs, read paths bypassing `.read`, and intentionally different
malformed-file behavior remain explicitly unverified. A passing count comparison
must not be presented as passing those additional reading contracts. Writing,
in-place Python object manipulation and numerical statistics are not production
APIs of this I/O crate; writer tests still provide useful generated reader inputs.

## Reproduction

Use a test-only Python environment. Exact packages used for this run are in
`fabio-parity/reference-requirements.txt`; Python is not used by the Rust reader
or its tests. Keep the downloaded corpus outside the repository.

```sh
python3.13 -m venv /tmp/dioptrin-io-fabio-suite-env
/tmp/dioptrin-io-fabio-suite-env/bin/python -m pip install -r docs/fabio-parity/reference-requirements.txt
git clone https://github.com/silx-kit/fabio.git /tmp/dioptrin-io-fabio-2026.6.0
git -C /tmp/dioptrin-io-fabio-2026.6.0 checkout 9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece
cargo build --locked --example parity_probe --features wrappers
/tmp/dioptrin-io-fabio-suite-env/bin/python scripts/fabio_suite_parity.py \
  --fabio-source /tmp/dioptrin-io-fabio-2026.6.0 \
  --data /tmp/dioptrin-io-fabio-corpus \
  --report /tmp/dioptrin-io-fabio-acceptance.json
```

Omitting `--modules` is essential for the full inventory. A selected-module run
records that restriction in its report. The exact source commit is checked, and
installed reference codec hashes must match the pinned sources for a green gate.

The upstream test utility's old edna-site HTTPS endpoint has a certificate-host
mismatch on this host. The harness explicitly uses the working official
`https://www.silx.org/pub/fabio/testimages` mirror, retaining file hashes. The
test environment explicitly registers its installed hdf5plugin codecs
(`--reference-filters bundled`, the default), preventing unrelated host HDF5
plugins from causing ABI conflicts. This policy is recorded and does not affect
the production native reader. OpenJPEG must be discoverable separately for the
optional Glymur test variants; the Pillow JPEG2000 tests run independently.

## Current evidence and remaining work

The checked report under `fabio-parity/` is a failing acceptance baseline, not a
parity claim. Every original registry entry remains in the coverage ledger.
The harness currently adapts NPY, raw binary, d*TREK/ADSC, Fit2D masks and
spreadsheets, HiPiC, PNM, CBF, EDF and generic TIFF. HDF5 detector discovery,
remaining codecs and semantic detector headers still require implementations
and explicit comparisons.

The same-file corpus revealed real cases now supported: nested braces inside
d*TREK values, repeated HiPiC comment keys, EDF binary padding, absent optional
uncompressed Size, legacy compression names, and outer gzip/bzip2 wrappers.
Small independent CC0 regressions complement these files, particularly for
native types, C/Fortran indexing, bounds, truncation and mutation.

Some reference tests intentionally accept incomplete data and fill missing EDF
pixels with zeros. Others tolerate compression garbage, malformed headers or
drop text fields. These are visible native rejections/header differences, not
permission to invent counts or silently repair a source. The repository's
count-preservation contract takes precedence, and each such difference must be
resolved or documented explicitly. The pinned PNM P1/P2 implementation also
fails to advance its row index; native input preserves all rows rather than
adopting that bug. Reference quirks do not remove any format from the target.
