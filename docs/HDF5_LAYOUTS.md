# Exact HDF5 types and external raw windows

The typed HDF5 image reader continues to expose 2D images and 3D stacks without
orientation changes or numerical corrections. The existing bundled HDF5 decoder
handles compression and ordinary selections; no second compressed decoder or
parallel fast path is introduced.

Supported exact types now include the standard integer/f32/f64 types and:

- Packed complex64/complex128 compounds with members `r` at offset0 and `i` at
  offset4/8, exactly two same-endian IEEE f32/f64 members, total size8/16. Output
  is `C32`/`C64`, with original real/imaginary order and component bits retained.
  Renamed, padded, mixed-endian and other compound types are explicit gaps.
- The exact signed8 HDF5 enum `FALSE=0, TRUE=1` used by h5py bool. Output is
  `Bool(Vec<u8>)`; even noncanonical nonzero source bytes remain unchanged.
  Logical truth is a separate consumer interpretation. General enums are not
  silently converted to integer source types.
- Exact IEEE754 binary16 in either byte order. `F16(Vec<u16>)` contains the
  original binary16 words, including NaN payloads, signed zero and subnormals.
  No f32 promotion occurs. A half-safe source descriptor is provided when the
  upstream Rust descriptor enum lacks its optional half-float wrapper feature.

The shared attribute reader and scalar-fill access use the same exact native
memory datatypes. Attribute declarations, shape and source endian metadata remain
separate from the canonical native values. Complex NaN attributes compare by
component bits during NeXus graph revalidation. Explicit VDS declared-fill paths
also retain the new types without scalar promotion. Sparse component/event reads
preserve these stored types; deterministic dense reconstruction explicitly
rejects complex, Bool and binary16 intensities before applying its integer/f32/f64
model.

## Explicit external raw storage

Existing opens still reject HDF5 raw external storage. Callers may opt into:

```rust,ignore
typed::Reader::open_snapshot_with_storage(
    path, selection, options, optional_vds,
    Some(typed::ExternalRawOptions { filenames: &bindings }), origin,
)
```

Each `FilenameBinding` maps the exact stored filename to an explicitly selected
actual local file. Missing, duplicate or unused bindings fail the complete raw
selection. Ordinary datasets ignore irrelevant global maps. There is no basename
search, implicit relative lookup, filename substitution or missing-file fill.
External-link and VDS policies remain separate.

Only unfiltered contiguous external storage is admitted. Every declared file is
snapshotted, including reservations beyond the frozen dataset extent. Metadata
retains original filenames, actual files, physical offsets, finite/unlimited
reservations, logical offsets and effective frozen byte lengths. Every byte of
the frozen dataset must have an available source window. A future reservation
may exceed the current physical payload only where it contributes no current
samples. Unlimited is a final HDF5 reservation declaration, never an unbounded
read. HDF5's original allocation/fill metadata is retained independently of the
physical window proof.

Raw payload bytes are read only from those admitted file handles/windows, then
component endian order is converted in place. HDF5 never performs external-file
sample lookup. Windows may split a scalar or complex component; logical byte
concatenation is exact. Padding before/after windows never becomes counts.
Snapshots and requested-path aliases for every HDF5/raw file are checked before
and after reads. Raw dataset path/object bindings and frozen graph dimensions
are also rechecked, including unflushed unlink/rebind and shape changes. Failed
reads hide reused output. File metadata checks have the existing immutable-source
contract and do not claim protection against adversarial writes preserving all
identity/timestamp metadata.

Frame/chunk and source/member/text limits remain independent. Window and binding
metadata is admitted before retained allocation; filename scratch is bounded by
both text and metadata limits. These accounting domains do not include native
HDF5 caches or promise total process RSS. This manual unfiltered window reader
has no throughput claim.

## Independent evidence and remaining scope

`tests/data/hdf5-layouts/` contains small CC0 fixtures generated by
`scripts/generate_hdf5_layout_fixtures.py`. Hand-chosen component words cover
NaNs with payloads, infinities, signed zero, extrema/subnormals and raw bool bytes
0/1/2/127/128/255. The raw example splits big-endian complex data at byte13 across
two physical files, with source prefixes/trailers and a final unlimited
reservation. A separate complex VDS verifies original fill component bits.

Eight focused Rust tests cover exact samples/attributes/fill, source and alias
changes, incomplete/missing/wrong maps, limits and sparse model rejection. The
existing typed, VDS, NeXus and sparse regression suites also pass. Three Python
controls ensure dtype, shape, IEEE bits, component order and bool byte differences
cannot pass by numerical equality alone.

The test-only `scripts/hdf5_layout_reference.py` compares all admitted image
words to independently specified fixture words, h5py and unchanged pinned
FabIO2026.6.0 `Hdf5Image` calls. It separately checks source windows, graph files,
fill and exact attributes. Reference raw-external calls use a recorded exact
source directory with `HDF5_EXT_PREFIX` unset; production uses only explicit
bindings. Reference failures remain failures, rather than triggering a retry.
The generated report pins source, executable and reference module hashes.

Arbitrary enums, renamed/padded/mixed-endian compounds, native HDF5-2 complex
types and other custom precision/layout variants remain valid unsupported image
types. Rank1/rank4 and empty image axes remain outside this 2D/3D image API;
the pinned `Hdf5Image.read` also explicitly rejects ranks other than 2/3.
Nested/printf VDS, unlimited irregular mappings and VDS modules with external
raw storage retain their explicit rejection. Finite irregular mappings now have
the separately qualified contract in [VDS_READER.md](VDS_READER.md). This
extension does not claim arbitrary HDF5 datatype grammar or general n-dimensional array support.

The [frozen proof](hdf5-layouts/2026-11-06-types-external.json) passes all source,
probe and pinned-reference gates: **9 admitted datasets, 12 complete image
frames and 7 exact typed attributes**. All nine unchanged `Hdf5Image.read`
calls complete and every frame matches the independent words and h5py source.
Six valid unsupported datatype/rank variants remain separately recorded; the
pinned reference also rejects rank1/rank4 as outside its image contract.
