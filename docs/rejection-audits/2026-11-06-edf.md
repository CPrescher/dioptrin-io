The [machine-readable audit](2026-11-06-edf.json) classifies all 68 EDF rejection
events (16 baseline source hashes) from `2026-11-05-mar-sparse.json`. An event is
an upstream-suite read attempt, so repeated reads of one source are counted
separately. The input condition and native reader action are separate fields.

This set contains no demonstrated well-formed unsupported native EDF codec.
The 42 compatibility closures do not establish that these files satisfy the
default declared-window contract. EDF volumes, float128 and byte-offset remain
outside this audit's support claims.

## Explicit external-window policy

`edf::Options.external_window` defaults to `edf::ExternalWindow::Exact`.
The complete external read window must exist, including declared padding.
`UpToDeclared` explicitly admits an oversized external read request by reading
at most the bytes available after the checked offset. It retains
`Metadata.declared_stored_bytes`, the effective `Metadata.stored_bytes`, and
`Metadata.external_window_policy`. Original header bytes and fields remain
available. Inline metadata has policy `None`; inline physical block bounds and
frame navigation remain exact.

The effective window still obeys the encoded-byte limit. All raw sample bytes,
or the complete compressed stream producing exactly the declared sample bytes,
must exist. There is no count padding, alternate codec retry or partial frame
sequence recovery. Original and staged source snapshots remain checked before
and after reads. Source discovery, basename relocation and compressed external
counterparts remain separate explicit options.

Both rh28a header files describe 20 U16 images of shape `[120,120]`. Each external
expanded source contains 37,376 bytes with image data starting at offset 8,192:
29,184 bytes remain, and each image needs 28,800 bytes. Frames 0–16 request
28,800 bytes, frame 17 omits the window and defaults to 28,800, frame 18 requests
29,184, and frame 19 incorrectly requests 140,000. The pinned upstream test calls
this a [wrong EDF_BinaryFileSize that exceeds the real file size](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/test/codecs/test_edfimage_expg.py#L417-L431).
That test motivates compatibility; it is not a normative EDF specification
establishing that a declared window is generally optional. With `UpToDeclared`,
all 20 frames from each header file have exact dtype, shape and full sample-byte
SHA-256 agreement with pinned FabIO. Exact policy rejects both files.

## Strict rejections with complete sample bytes

The split MultiFrame files contain F32 images of shape `[1043,981]`, needing
4,092,732 bytes. Their actual headers are 2,048 bytes (frame 0) and 1,024 bytes
(frame 1); each has exactly the necessary samples after its header. Both retain
`EDF_HeaderSize=8192` and `EDF_BinarySize=4092928`, requesting 196 bytes beyond
EOF. The legacy `Size=4092732` agrees with the samples. In the unsplit source,
the larger binary size includes real 196-byte padding after each frame. FabIO
[overwrites its binary size with legacy Size](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/edfimage.py#L371-L376).
Native EDF retains its declared physical-block contract. An explicit existing
`native::Reader::open_raw` layout reproduces every split sample and dtype,
including the independently expanded bzip2 source. This is evidence of complete
samples, not automatic EDF acceptance or a new inline fallback.

`d80_60s.edf` has a 2,560-byte actual header, stale `EDF_HeaderSize=3072`, and
16,777,216 raw sample bytes for `[2048,2048]` I32. Its `Compression=TY1`, `OI` and
`OL` would imply an 8,692,088-byte TY1 encoding, which the payload does not use.
The first raw sample is 0; interpreting its first byte as TY1 would yield −127.
The explicit raw layout matches both FabIO's EDF output and the decoded actual
Oxford `d80_60s.img` sample bytes exactly. The pinned EDF reader has
[no TY1 decode branch and treats an unknown compression label as raw](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/edfimage.py#L601-L635).
The corresponding [Oxford test compares these two files](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/test/codecs/test_oxdimage.py#L144-L160).
Adding a TY1 EDF decoder would not correctly decode this mislabeled raw payload.

## Deliberately truncated inputs and provenance

Pinned [bad-file tests](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/test/codecs/test_edfimage.py#L685-L776)
expect incomplete sequences, incomplete data or zeros; FabIO
[pads missing samples](https://github.com/silx-kit/fabio/blob/9ddb6f6ce22e79056bec0f6e6b97d7ebc29cbece/src/fabio/edfimage.py#L630-L650).
These are intentional invalid inputs rather than native missing-codec cases.
The native immutable complete-source contract keeps all ten rejected.

The five uncompressed bad-file sources were captured with exact original
baseline SHA-256 hashes. The five old gzip envelopes had already been deleted
by upstream cleanup. Re-running the same test supplied recreated sources with
different gzip timestamps and compressed hashes. Each audit record retains the
original baseline hash and test IDs, separately labels recreated evidence, and
records the available copy's current hash. These five records make no claim of
exact original compressed-byte reproduction. Overall, 63 of the 68 events have
exact baseline source bytes available. Capture manifests, source hashes,
expanded-prefix hashes, offsets, declared/available/required sizes and pinned
primary-source file hashes are recorded in the JSON.

## Reproduction and independent checks

The scoped audit is read-only and does not run upstream writers:

```sh
cargo build --no-default-features --features edf,native --example edf_rejection_probe
/tmp/dioptrin-io-fabio-suite-env/bin/python scripts/audit_edf_rejections.py
```

It uses the pinned FabIO 2026.6.0 reference source and preserved external corpus
and rejection captures under `/tmp`; these large inputs are excluded from Git.
The probe uses native readers and hashes canonical little-endian full samples.
The scoped raw mode requires explicit dimensions, offset and type and is used
only for the complete-sample proofs described above. No performance claim is
made.

`tests/edf_windows.rs` generates independent CC0-1.0 fixture bytes without an
upstream writer. It covers default-versus-explicit policy, exact U16 counts and
metadata, missing samples, invalid offsets/windows, unchanged inline bounds,
effective encoded budgets, source replacement, wrapped sources, and truncated,
short-output and long-output internal GZIP/ZLIB/BZ2 streams. These fixtures test
nonzero/reserved counts independently of the external reference corpus.
